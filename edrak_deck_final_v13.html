Architecture Workflow

System Architecture

All four workers and the gate currently run on gpt-oss-120B. Tokens are metered per call, not per agent.
Tracing · evaluation

Every run leaves a trace; evaluation reads it

The evaluation agent reviews saved outputs. It never reruns workers, retrieval or tools, and makes no business decisions.

Unique selling proposition

Unique Selling Proposition

01
Shows what it couldn’t confirm

Failed findings stay visible as gaps, never passed on as facts.

02
Confidence per recommendation

LOW / MEDIUM / HIGH tied to its evidence. No valid evidence means LOW.

03
A person stays in control

Approves the plan before it runs, then decides.

04
Your own data first

Internal documents are a primary source; every recommendation traces to evidence.

EXTRA
Fixed brief schema + scoring

Consistent output; per-run quality scoring on one test case.

Competitors also advertise “cited” and “verified”. We did not find claim-level gating, per-recommendation confidence or gap reports on their public pages. Not yet tested head-to-head.

FP4 (NVFP4)

4-bit KV cache, so more context fits in 32 GB.

CONTEXT
20K · 64K tokens

20K is our longest observed call; 64K is headroom for future use.

Model (FP4 weights)KV poolKV cache typeKV per tokenKV per sequence @20KKV per sequence @64K

Qwen3.5-9B · 9.4 GB18.6 GBFP4 (NVFP4)9 KiB0.22 GB0.61 GB
KV pool = 32 GB − weights − 4 GB overhead. KV per token = 2 × full-attention layers × KV heads × head dim × bytes (27B: 16×4×256; 9B: 8×4×256); FP4 = 0.5625 bytes per value (4-bit plus scales); plus a fixed recurrent state per sequence (27B: 0.15 GB; 9B: 0.05 GB). Memory estimate only; benchmark needed. A 4-bit KV cache needs TensorRT-LLM with offline ModelOpt quantization, and its docs currently pair it with FP8 weights; test accuracy before relying on it.
